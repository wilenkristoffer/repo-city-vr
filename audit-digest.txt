=== HIGH (9) ===
- [CityLayout.cs] When a repo has zero files, districtCount is 0, so the bounds-accumulation loop never runs and minX/maxX/minZ/maxZ are left at their float.MaxValue/float.MinValue sentinel seeds, producing an inverted CityBounds that downstream code turns into an infinite/negative ground-plane scale.
- [RepoData.cs] Neither RepoDataLoader.Load nor CityLayoutBuilder.Compute checks that the deserialized RepoData.files list is non-null before iterating it, so a structurally-valid-but-incomplete repo-data.json crashes city generation with an unhandled NullReferenceException instead of the helpful error the missing-file case already gets.
- [WorldBuilder.cs] Traffic and pedestrian loop waypoints are captured in the island's pre-shift (local-origin) coordinate frame, then the island is moved to its real worldCenter afterward, leaving every car/NPC chasing stale, wrongly-offset target points on every island except the first.
- [RoadNetwork.cs] Resources.Load results for road prefabs are passed straight into Object.Instantiate with no null check, unlike every other spawner in the codebase (TrafficSpawner, VegetationScatter, NpcSpawner all guard with `if (prefab == null) continue;`).
- [MiniLang.cs] The hand-written recursive-descent parser (and the matching tree-walking interpreter) has no nesting-depth limit, so arbitrarily deep parenthesization, unary chains, or brace nesting recurse the C# call stack without bound, and a deep-enough input throws an uncatchable StackOverflowException that kills the whole Unity process.
- [MiniLang.cs] maxSteps bounds the number of statement executions, not the cost or memory allocated per step, so a test case whose per-iteration work grows exponentially (e.g. string doubling) can exhaust memory or stall the main thread long before the 200,000-step ceiling is ever approached.
- [CodeKiosk.cs] The kiosk's only interaction path is a legacy UGUI Button/InputField pair driven by `GraphicRaycaster` + `StandaloneInputModule`, which resolves pointer position from `Input.mousePosition` — there is no XR ray interactor / TrackedDeviceGraphicRaycaster anywhere in this file or wired to it, so in VR there is no way to position a pointer over the kiosk at all.
- [CityLayout.cs] When a repo has zero files, districtCount is 0, so the `for (d in 0..districtCount)` loop that updates minX/maxX/minZ/maxZ from float.MaxValue/float.MinValue sentinels never executes, and Compute() returns a CityBounds with minX=float.MaxValue and maxX=float.MinValue (inverted, maximally-sized) instead of a sane empty-bounds value.
- [MiniLang.cs] The 200000-step limit guards against runaway `while` loops (each loop iteration calls Execute() at least once) but does nothing to bound recursion depth from a single large/deeply-nested expression, so a sufficiently long or deeply-parenthesized line of code typed or pasted into a CodeKiosk's input field recurses the C# call stack without limit during both parsing and evaluation.

=== MEDIUM (7) ===
- [CityBuilder.cs] Only material slot 0 of the found renderer is recolored; any building model whose renderer has more than one material slot (e.g. separate wall vs. window/trim materials, common in low-poly building packs) keeps its original un-jittered material on every other slot.
- [Locomotion.cs] Both hands' teleport-aim visuals are drawn onto one shared LineRenderer and one shared marker object instead of per-hand instances, so holding both triggers at once makes the second hand's call silently overwrite the first hand's displayed arc/landing marker.
- [SceneBootstrapper.cs] A stale narration/NPC-chat coroutine from a previous inspection is never stopped when superseded - only its eventual callback result is discarded via the inspectToken check - so the coroutine (and whatever network/IO call it wraps inside OllamaNarrator.GetNarration / NpcChat.GetLine) keeps running to completion regardless.
- [NpcController.cs] Unlike the GameObject prefab cache (prefabCache dictionary) used in NpcSpawner.Spawn for the same character models, the per-NPC AnimationClip lookup in NpcWalker.Init/SetupAnimation is never cached, so every single NPC instance re-runs Resources.LoadAll for its model even when a prior NPC already loaded the identical clip set.
- [WorldBuilder.cs] If an exception is thrown after islandRoot and its children (city, roads, vegetation, traffic, NPCs) have already been instantiated but before `islandRoot.transform.localPosition = worldCenter` runs (line 61), the catch block logs a warning and moves on without destroying islandRoot - the partially-built island is left alive in the scene at local (0,0,0) (i.e. overlapping island 1 / the parent's origin) even though it's described as 'skipped' and is never added to `results`.
- [CodeArcadeBuilder.cs] The sign and every kiosk's world-space canvas are oriented on the assumption that the player approaches Programming Central from -Z, but WorldBootstrapper places the arcade to the WEST of the home island (`arcadeX = home.worldCenter.x + homeLayout.bounds.minX - 60f`, at the home island's own Z) while the player spawns to the NORTH of the home island - so the walk from spawn to the arcade is dominated by movement along -X, not -Z.
- [CityBuilder.cs] Finding each district's tallest building for label placement re-scans the entire city-wide buildings list for every district, giving CityBuilder.Build() an O(districts * totalBuildings) startup cost instead of an O(buildings) single pass (e.g. tracked per-district while building, or a dictionary keyed by district).

=== LOW (7) ===
- [CityBuilder.cs] Computing each district label's height scans the entire city-wide buildings list once per district, giving O(districts * total buildings) work during city construction instead of a single pass that tracks per-district max height.
- [RepoData.cs] The missing-file case (asset == null) gets a clear, actionable exception message, but a present-yet-malformed or truncated repo-data.json makes JsonUtility.FromJson throw its own unhandled, unhelpful exception.
- [WorldBootstrapper.cs] Unlike SceneBootstrapper, which wraps its equivalent single-city construction (RepoDataLoader.Load/CityLayoutBuilder.Compute/CityBuilder.Build) in a try/catch with a friendly Debug.LogError, WorldBootstrapper has no top-level try/catch around WorldBuilder.BuildAll - only WorldBuilder's internal per-island try/catch protects against a single bad repo, so any exception that occurs outside that inner per-island try (e.g. a static initializer fault in WorldConfig, or any future change to BuildAll's setup code before/after the per-island loop) propagates as an unhandled exception that aborts Start() with no diagnostic message, leaving only the Sun/lighting already set up and an otherwise blank scene.
- [SceneBootstrapper.cs] When loading/building the city throws (e.g. missing repo-data.json), the catch block logs an error and returns before any Camera is ever created, so if the scene has no pre-existing Main Camera the player is left facing a fully blank screen with the only diagnostic going to a console that isn't visible from inside a VR headset.
- [NpcChat.cs] EscapeJsonString appends literal raw newline/carriage-return/tab characters (`sb.Append("\n")` etc., a C# escape producing an actual control character) instead of the two-character JSON escape sequences (`\\n`, `\\r`, `\\t`) that the sibling implementation in OllamaNarrator.cs correctly produces, so any prompt string containing those characters would be embedded as an unescaped control character inside a quoted JSON string, which is invalid JSON.
- [CodeKiosk.cs] MiniLang error messages report line numbers against the concatenated setupCode+playerCode source, not the player's own code, so the on-screen error line number is wrong by the setupCode's line count whenever setupCode spans more than one line.
- [HudPanel.cs] Legend swatches are laid out at a fixed 12-unit vertical step inside a legend region whose own rect height is fixed (~86 units regardless of category count), with no clipping mask and no scaling of the step to the available space, so once there are more than ~7 distinct building categories in use the swatches (and their label lines) run past the legend's background and can visually collide with other HUD text.
